# v1.0.0 への移行で hyoui が踏んだ点 (値の入った欄が黙って消える、INDEX の題名が切れる)

hyoui の統括セッションからの報告 (2026-11-15、plugin 1.0.0、active な issue 61 件のリポ)。利用側からは観測と困った点の提示に留める。採否と直し方は、裏を取ってからこのリポの側で決めてほしい。「使っていなかったが無くなった」だけの点 (`last_read`、`*_entered` の時刻、sub-command) は挙げていない。

## 1. 値の入った欄が、指摘なしに消える (実害あり)

### 観測

起動時の検査で 60 件が直された。消えた欄のうち値が入っていたものを VCS の差分で数えた:

| 欄 | 値が入っていた件数 | 中身 |
|---|---|---|
| `last_read` / `open_entered` / `wip_entered` / `blocked_entered` / `pending_entered` | 31 / 58 / 3 / 6 / 1 | 時刻。使っていなかった |
| `pending_reason` | 1 | 文章 (保留にした理由) |

`pending_reason` の 1 件は `docs/issue/2026-10-09-bug-child-action-menu-closed-by-echoed-ctrl-z.md` で、値は「kawaz 2026-10-09『menu は使っていないので要らない。自前の仮想セル層 (DR-0040) ができた時に考え直す』。menu は既定では出ない …」。この issue を保留にした根拠はこの欄にしか書かれておらず、本文には無かった。

### 困った点

- 整理の後、ファイルには `status: pending` (使えない値、という指摘つき) だけが残り、なぜ保留なのかが読めなくなった。指摘に従って status を直そうとした時、`open` か `blocked` かを決める材料がファイルに無かった
- 起動時のまとめは「直した 60 件」のうち 4 件だけを列挙し「ほか 56 件」だった。値の入った文章の欄が消えたファイルがどれかは、まとめからは分からなかった。VCS の差分を自分で調べて見つけた
- 利用側の対応: 差分から理由を拾い、本文に「保留の理由」の節として移し、`status: blocked` + `blocked_by` にした

### 検討してほしいこと

表に無い欄を消す時、値が時刻でない文章の場合の扱い。案としては、消さずに指摘する (本文へ移すよう促す) か、消したことを「値のあった欄」として起動時のまとめで別に知らせる。`discard_reason` も同じ形の欄 (hyoui の active には値入りが無かったので未観測)。

## 2. INDEX の題名が 60 文字前後で切れる (実害は未経験)

### 観測

- 生成された INDEX の 61 行のうち 34 行で、題名が `…` で切れている
- 例: `配布している macOS のバイナリが ad-hoc 署名 (linker が付けたもの) で、hardened run…`、`discovery の test 2 本が並行実行で 4 回に 1 回落ちる (長い socket path の for…`
- 移行前の INDEX は `| date | category | status | slug | 概要 |` で、概要の列に 1 文の要約と次の動き (「現版で再現確認して出なければ close」「kawaz 裁定」等) を書いていた。新しい INDEX にはこの列が無く、題名が代わりになる

### 困りうる点

- 題名の後半に区別の決め手がある issue (同じ書き出しで原因や条件だけ違うもの) が、INDEX の上で見分けにくい
- 「次に何をすれば閉じられるか」が INDEX から読めなくなった

このセッションでは INDEX を読んで着手する issue を選ぶ作業をしていないので、実際に困ってはいない。題名を切る幅を決めた理由があるなら、そのままでよい。

## 3. 参考: 移行で残る古い記述 (plugin の外)

plugin の不具合ではないが、移行時に利用側で直す必要があった / あるもの。移行の案内に入れる材料として。

- hyoui の `docs/issue/README.md` が「close したら削除」「prefix で状態を表す」のままで、v1 の「archive へ移動」「status で管理」と逆になっている (hyoui 側で書き直す)
- claude-rules-personal の reference `docs-authoring/docs-layout` の issue の節が「運用の正本は sub-command (`write` / `read` / `update` / `list` / `migrate`)」「起票は `write` で行い手書きしない」のまま

## 良かった点 (変えないでほしいもの)

- 起票・更新の追加コストが 1 行になった。旧版は 1 回ごとに別 agent が立ち、約 7 万トークンと 15〜20 秒かかっていた (2026-11-13 に 4 回)
- plugin が commit しない。旧版は毎回「commit したが確認していない」と返り、呼び出し側が確かめ直していた
- 指摘が「何がおかしいか」と「どうすればよいか」を 1 行で伝える
- `INDEX.md を更新した` の 1 行で、パスを絞った commit に INDEX を入れ忘れない
